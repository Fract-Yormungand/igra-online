# 001. Сервер считает добычу, мир генерируется на обеих сторонах

Статус: принято
Дата: 2026-11-06

## Контекст

Нужна сетевая игра, где игроки сразу подключаются, ходят по площадке и
добывают ресурсы. Нельзя давать клиенту начислять себе предметы: иначе
первый же чит ломает экономику. При этом трафик и сложность надо держать
низкими, а тестировать всё нужно без ручных прогонов.

## Решение

1. Сервер авторитетен для добычи, инвентарей и состояния источников.
   Клиент отправляет только заявку `_request_harvest(источник)`, сервер
   проверяет дистанцию, инструмент и остаток ударов, и рассылает результат.
2. Позицию персонажа считает клиент и присылает 15 раз в секунду. Сервер
   хранит последнюю известную позицию и использует её только для проверки
   дистанции.
3. Мир генерируется кодом на обеих сторонах по одному сиду. По сети едет
   только состояние источников, а не геометрия.
4. Справочник предметов и правила добычи живут в чистых статических классах
   без сцен и сети, чтобы прогоняться тестом в headless-режиме.

## Почему так

- Авторитет сервера на добыче убирает накрутку ресурсов и делает отказы
  объяснимыми: клиент получает текст причины.
- Детерминированная генерация убирает необходимость синхронизировать 81 объект
  при входе и снимает расхождения геометрии.
- Чистое ядро даёт быстрые тесты: 71 проверка правил и генерации идёт без
  окна и без сети.
- Клиентская позиция это осознанный компромисс на старте: серверная физика
  дороже и требует предсказания движения на клиенте.

## Последствия

- Телепорт и ускорение клиентом возможны, ловится только проверка дистанции.
  Дальше нужен серверный расчёт движения с предсказанием и коррекцией.
- Любое изменение правил идёт через `Rules` и `ItemDB`, иначе клиент и сервер
  начнут расходиться.
- Время возрождения считается на сервере по часам процесса, у клиента своих
  таймеров нет.

## Альтернативы

- Полностью серверная физика сразу: дороже по времени, отложено до этапа,
  где появятся бои и античит требования.
- Передача геометрии мира по сети: лишний трафик и лишняя точка отказа,
  отклонено.
